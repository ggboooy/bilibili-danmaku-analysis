**这是公开接口当前可获取样本的统计，不是全部历史弹幕，也不是所有观众的意见调查。**

|---|---|---:|---:|---:|

## 统计方法与限制

1. 通过 B 站视频信息、XML 弹幕及分段弹幕公开接口获取数据，以弹幕 ID 合并去重，共 1,855 条。视频信息接口显示总弹幕 9,136 条。历史弹幕接口返回“账号未登录”，没有获取到全部历史弹幕。
2. 所选时段内有 875 条弹幕、773 个用户标识。时段依据回应密集区选取，未独立转写视频音频。
3. 将文本做 NFKC 规范化，转小写并去除标点、空白分隔符和符号，然后用明确的匹配词集合分类。匹配词表完整保存在统计 JSON 中。
4. 同一用户多次发送不同 ID 的弹幕，条数分别计算，用户数按 `user_hash` 去重。匿名哈希不是经过核验的真实身份，理论上可能碰撞。
5. 未把泛泛的“BLG 加油”、评论其他弹幕或含糊表达计入直接回答。“未纳入”不等于中立。
6. 分类字段覆盖全部已获取弹幕；计算上述结果时，必须先筛选 `in_window_25_to_60_seconds = true`。Excel 中对应“位于统计时段”为“是”。
7. 把范围扩为 00:00—01:00 后，同义口径积极为 57 条／54 个标识，消极为 471 条／421 个标识。
8. 当前样本不是随机抽样，不应使用上述比例推算全部历史弹幕或所有观众态度。

## 明细字段

| JSON 字段 | 含义 |
|---|---|
| `id` | 弹幕 ID，以字符串保存，避免大整数精度丢失 |
| `progress` | 视频播放时间，单位为秒 |
| `text` | 弹幕原文 |
| `user_hash` | 接口返回的匿名用户哈希，用于本次去重 |
| `ctime` | 弹幕发送时间，Unix 时间戳（秒） |
| `normalized_text` | 用于匹配的规范化文本 |
| `in_window_25_to_60_seconds` | 是否位于 25—60 秒，含端点 |
| `literal_classification` | 仅“好／不好”的分类 |
| `classification` | 计入明确同义回应的分类 |

分类取值为 `positive`（积极）、`negative`（消极）、`excluded`（未纳入）。Excel 里的序号仅方便定位，不参与去重。Excel 用户数为这次快照的去重结果，编辑明细后需重新计算。

## 数据接口

- 视频信息：`https://api.bilibili.com/x/web-interface/view?bvid=BV1xc4x6QEEA`
- XML 弹幕：`https://comment.bilibili.com/43425008909.xml`
- 分段弹幕：`https://api.bilibili.com/x/v2/dm/web/seg.so?type=1&oid=43425008909&segment_index=1`（同时获取第 2 段，并合并一次带 `ps=0&pe=360000` 参数的第 1 段返回结果）

JSON 是这次采集后整理的快照，不是 B 站全量原始数据库。原文包含部分用户的粗俗表达，保留原文是为了复核分类。
